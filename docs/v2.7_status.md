## 📋 Workflow de Programaciones

### 1. Creación de Programación
1. Usuario accede a `/schedules`
2. Hace clic en "Nueva Programación"
3. Completa el formulario con todos los campos
4. Guarda la programación
5. Sistema crea registro en `panel_schedules`

### 2. Verificación Automática
1. Sistema recibe mensaje de cámara
2. Actualiza ocupación del parking
3. **Verifica programaciones activas** para el parking
4. Si hay programación activa:
   - No actualiza paneles
   - Mantiene mensaje programado
5. Si no hay programación activa:
   - Actualiza paneles con estado actual
   - Restaura funcionamiento normal

### 3. Ejecución de Programación
1. Sistema detecta que es hora de ejecutar programación
2. Obtiene paneles online del parking
3. Envía mensaje programado a todos los paneles
4. Registra log de ejecución en `panel_schedule_logs`

### 4. Finalización de Programación
1. Sistema detecta que terminó el horario de programación
2. Obtiene estado actual del parking
3. Envía mensaje de estado a todos los paneles
4. Registra log de finalización

## 📊 Métricas y Logs

### Logs de Programaciones

**Tipos de Log:**
- `started`: Programación iniciada
- `ended`: Programación finalizada
- `skipped`: Programación omitida (sin paneles online)
- `error`: Error en ejecución

**Información Registrada:**
- ID de programación
- ID de parking
- Tipo de ejecución
- Mensaje enviado
- Número de paneles afectados
- Timestamp de ejecución

### Consultas Útiles

```sql
-- Programaciones activas por parking
SELECT p.name as parking_name, ps.name as schedule_name, ps.message
FROM panel_schedules ps
JOIN parkings p ON ps.parking_id = p.id
WHERE ps.is_active = true
AND ps.start_date <= NOW()
AND ps.end_date >= NOW();

-- Logs de ejecución recientes
SELECT ps.name, psl.execution_type, psl.message_sent, psl.panels_affected, psl.executed_at
FROM panel_schedule_logs psl
JOIN panel_schedules ps ON psl.schedule_id = ps.id
ORDER BY psl.executed_at DESC
LIMIT 20;
```

## 🔄 Servicio de Monitorización

### Arquitectura del Monitor

**`ScheduleMonitorService`** es un servicio independiente que se ejecuta en segundo plano y monitoriza continuamente las programaciones para ejecutarlas automáticamente.

#### Características Principales

- **Monitorización continua**: Verifica programaciones cada 60 segundos
- **Ejecución automática**: Activa programaciones según horarios configurados
- **Prevención de duplicados**: Evita ejecuciones múltiples de la misma programación
- **Finalización automática**: Detecta cuando terminan programaciones y restaura estado
- **Logging detallado**: Registra todas las operaciones para auditoría

#### Configuración del Servicio

**Archivo de servicio systemd**: `deploy/parking-schedule-monitor.service`
```ini
[Unit]
Description=Parking Altea Schedule Monitor Service
After=network.target parking-api.service
Wants=parking-api.service

[Service]
Type=simple
User=root
WorkingDirectory=/root/parking_altea/src
ExecStart=/usr/bin/python3 /root/parking_altea/src/schedule_monitor_service.py
Restart=always
RestartSec=10
```

#### Instalación y Configuración

**Script de configuración**: `deploy/setup_schedule_monitor.sh`
```bash
# Ejecutar en el servidor
chmod +x deploy/setup_schedule_monitor.sh
./deploy/setup_schedule_monitor.sh
```

#### Comandos de Gestión

```bash
# Iniciar servicio
systemctl start parking-schedule-monitor

# Detener servicio
systemctl stop parking-schedule-monitor

# Ver estado
systemctl status parking-schedule-monitor

# Ver logs en tiempo real
journalctl -u parking-schedule-monitor -f

# Habilitar inicio automático
systemctl enable parking-schedule-monitor
```

#### Lógica de Ejecución

**Flujo de monitorización:**
1. **Verificación periódica**: Cada 60 segundos
2. **Análisis de programaciones**: Busca programaciones activas para el momento actual
3. **Verificación de condiciones**:
   - Fechas de vigencia (start_date ≤ now ≤ end_date)
   - Día de la semana activo
   - Horario actual (start_time ≤ now ≤ end_time)
   - Estado activo (is_active = true)
4. **Ejecución**: Si se cumplen todas las condiciones, ejecuta la programación
5. **Prevención de duplicados**: Usa cache para evitar ejecuciones múltiples
6. **Finalización**: Detecta cuando terminan programaciones y restaura estado

#### Verificación de Finalización

**Detección automática de finalización:**
- Monitoriza programaciones que acaban de terminar (último minuto)
- Restaura automáticamente el estado del parking en los paneles
- Registra logs de finalización para auditoría
